STEP 2 - WHY IT HAPPENS (Root Cause)
--------------------------------------------------------------------------------
1. `PUT ... @%TAXI_DRIVE_SMALL_FILES` is a SNOWFLAKE SQL statement. It only
   works inside a Snowflake client (Snowsight worksheet, snowsql, snow CLI,
   snowflake-connector-python).

2. The command above was pasted straight into PowerShell. PowerShell is NOT a
   Snowflake client, so it tried to parse the line as PowerShell code.

3. In PowerShell the `@` character is special:
       @  = an array literal, splatting operator, or start of a here-string.
   The sequence `@%TAXI_DRIVE_SMALL_FILES` is not valid PowerShell, so the
   parser threw  "Unrecognized token in source text."  at the `@` character
   (char 105).

   -> The SQL itself is fine. It is the SHELL that does not understand it.

STEP 4 - EXTRA NOTES ABOUT THE load.sql FILE
--------------------------------------------------------------------------------
1. Use the CORRECT file name (singular "record", matches the actual file):
       PUT 'file:///C:/.../train_100_record.csv' @%TAXI_DRIVE_SMALL_FILES;
   The second PUT in load.sql references train_100_records.csv (plural) which
   does NOT exist -> it will fail. Use the singular name or fix the file name.

2. `@%TAXI_DRIVE_SMALL_FILES` is the TABLE STAGE of table
   RAHUL_DB.PUBLIC.TAXI_DRIVE_SMALL_FILES. The `%` prefix means "stage created
   automatically for this table". You must be in (or fully-qualify)
   RAHUL_DB.PUBLIC for the unqualified `@%TAXI_DRIVE_SMALL_FILES` to resolve.

3. "Query result expired" errors on PUT are transient - re-run the PUT after:
       ALTER WAREHOUSE COMPUTE_WH RESUME;
       ALTER SESSION SET USE_CACHED_RESULT = FALSE;
