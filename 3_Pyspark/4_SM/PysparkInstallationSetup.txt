5. HOW TO USE IT IN VS CODE
------------------------------------------------------------------

A) LOCAL PySpark (recommended for learning):
   1. File > Open Folder > ...\DataWar\3_Pyspark
   2. Select the interpreter:
      Ctrl+Shift+P > "Python: Select Interpreter" > 3_Pyspark\.venv\Scripts\python.exe
   3. Open 2_Practice\00_First_Spark_Job.py (or any .py)
      - Run with the Python extension (Run Python File / F5)
      - Or Ctrl+Shift+B -> "PySpark: verify installation" (VS Code Task)
   4. Notebooks: create a .ipynb, kernel = 3_Pyspark\.venv, and use
      from pyspark.sql import SparkSession
      spark = SparkSession.builder.master("local[*]").getOrCreate()

B) DATABRICKS (run same file on a cluster):
   1. Open the 3_Pyspark folder (Databricks extension already installed).
   2. Ctrl+Shift+P > "Databricks: Configure workspace"
      -> pick profile "datawar" -> follow prompts (needs a running cluster).
   3. In a .py file: right-click > "Run Python File on Databricks Cluster"
      (or the Databricks action icon). The extension syncs the file and
      executes on your cluster; results return to VS Code.
   4. Deploy as a job later via the bundle: edit databricks.yml (fill real
      host), then:
        databricks bundle validate
        databricks bundle deploy
        databricks bundle run pyspark_smoke_job

6. NOTES / TROUBLESHOOTING
------------------------------------------------------------------
- Old "[DEFAULT]" profile still has placeholders (host/token/cluster_id).
  It is no longer the default. You can delete that section from
  ~/.databrickscfg or overwrite it with your real host via:
      databricks auth login --host <real-host> --profile DEFAULT
  (Backup of the original file: ~/.databrickscfg.bak)
- OAuth access tokens auto-expire (~1 h); the CLI refreshes them using the
  saved refresh token in the OS keyring. If you see auth errors, re-run:
      databricks auth login --profile datawar
- "databricks bundle validate" currently ends with
  "Missing required cluster ... Specify one of ... existing_cluster_id".
  This is EXPECTED until you create compute (section 4.4). The validation run
  already proves the connection works (it resolves your workspace + user).
  See also the HOW-TO comments inside databricks.yml.
- JAVA_HOME: keep pointing at the JDK 17 folder. Spark 4.x runs on
  Java 8/11/17/21 — do NOT switch to Java 25.
- pandas: use 2.x here (3.x triggers a PySpark FutureWarning and some
  features behave differently).
- Jupyter kernel "Python (.venv)" is selected by picking the venv for new
  notebooks or via "Jupyter: Select Interpreter to Start Kernel".
- "winutils.exe" warning is benign on Windows (documented above).
- VS Code "Databricks" runs need an internet connection to the workspace
  (OAuth + cluster). Local PySpark runs do NOT need internet.
